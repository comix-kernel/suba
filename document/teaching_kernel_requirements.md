# Comix 教学内核需求交接

## 项目目标与范围

基于现有 Comix，将内核裁剪到数千行，使读者可以通读源码，理解一个完整内核如何运行。裁剪应同时服务于教学和长期维护。维护者应能判断一项功能由哪个模块负责，修改它会影响哪些调用方，以及如何验证相关行为。

项目允许缩减 ext4、网络和 Linux ABI 的兼容范围。接手者需要从现有源码追踪这些能力引入了哪些依赖，再说明每项取舍。目前只约定了“数千行”这一规模，具体上限和统计口径仍待确定。

## 已确认的三个方向

三项要求作用在同一对象上。程序应当能用文件操作使用内核对象；实现者应当能按接口组合和替换提供该对象的组件；维护者应当能从顺序规则推断并发访问下的结果。

| 参考系统 | Comix 需要采纳的内容 |
| --- | --- |
| Plan 9 | 用文件树呈现内核对象。任务通过命名空间选择服务，经请求与回复使用对象。服务自身也能作为另一服务的客户端。 |
| Theseus | 让组件能依赖稳定接口，自由组合和替换相容实现。共享地址空间和特权级的方案需要用 Rust 的所有权和模块边界约束资源访问，说明替换时已有引用和状态的归属。 |
| NrOS | 让并发状态容易理解。先明确谁有权修改对象，对需要跨核一致的部分给出顺序语义，再说明更新顺序、可见时刻及副作用由谁执行。 |

上述要求对应的参考源码、首版机制和验收条件见[裁剪与重构设计](teaching_kernel_design.md)。
